How I work

bring-up habits

Follow the signal down

A symptom on screen is rarely where the bug lives. I chase it through composition, the HAL, the driver, the device tree and the rail underneath until the actual cause is named — then fix that, not the symptom.

Instrument before guessing

Bring-up is unusable without honest telemetry, so I build the tooling first: a desktop console for the test fleet, an on-device service and viewer, logs that tell you what is stale versus what is genuinely healthy.

Make it reproducible

If a fix only works on one bench it isn’t a fix. Containerised builds, layered overlays per hardware variant, and a signed artifact pipeline mean the same image boots the same way on every unit.
